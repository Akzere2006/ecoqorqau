# EcoQorgau

> **Жюри:** проверка и демонстрационный маршрут описаны в
> [`JURY_QUICK_START.md`](JURY_QUICK_START.md). После чистого clone достаточно
> выполнить `npm ci --no-audit --no-fund`, затем `npm run verify`.

**EcoQorgau** — универсальная PWA-платформа общественного экологического контроля Каспийского моря. Житель отправляет геопривязанное наблюдение, система рассчитывает объяснимый приоритет, а оператор ведёт обращение до публичного подтверждения результата.

Проект подготовлен для международного **Caspian Hackathon 2026** по направлению «Цифровые сервисы».

## Что уже работает в MVP

- адаптивный интерфейс для компьютера и телефона;
- установка на телефон как PWA;
- интерактивная геокарта Каспия на Leaflet с подложками «Атлас», «Рельеф» и «Спутник»;
- фильтры рисков, точные координаты, интерактивные маркеры и карточка выбранного сигнала;
- форма сообщения: категория, место, геолокация, описание, фото, срочность;
- прозрачный риск-скоринг с объяснением факторов;
- создание обращения и сохранение на устройстве;
- поиск и фильтрация единого реестра;
- карточка с хронологией обработки;
- переключение ролей «Житель / Оператор»;
- назначение ответственной команды и смена статуса;
- аналитическая панель на тех же данных;
- выгрузка реестра в CSV;
- индикатор сети и базовая офлайн-поддержка.

> В MVP используются демонстрационные данные и `localStorage`, что прямо разрешено ТЗ. Показатели эффекта отмечены как целевые, а не как уже достигнутые. Для пилота локальное хранилище заменяется PostgreSQL/D1 и защищённым API.

## Быстрый запуск

### Требования

- Node.js `22.13–24` (рекомендуется Node.js 22 LTS);
- npm `10+`;
- современный Chrome, Edge, Firefox или Safari.

### Windows / macOS / Linux

```bash
npm ci --no-audit --no-fund
npm run dev
```

Откройте адрес, который покажет терминал (обычно `http://localhost:5173`).

Полная кроссплатформенная проверка:

```bash
npm run verify
```

Она запускает ESLint, TypeScript, production-сборку, валидацию Worker artifact и
тест отрендеренного HTML. Такой же quality gate автоматически выполняется в
GitHub Actions на каждом push и pull request.

Команды `npm run dev`, `npm run build`, `npm run start` и `npm run verify`
одинаково работают в Windows PowerShell, macOS и Linux. `npm run build`
дополнительно проверяет итоговый Worker artifact.

## Демо за 2 минуты

1. На экране «Обзор» нажмите **Сообщить**.
2. Выберите тип проблемы, добавьте описание и перейдите к проверке.
3. Посмотрите, из каких факторов складывается приоритет, затем отправьте обращение.
4. В реестре назначьте команду и переведите обращение **В работу**.
5. Переключитесь в роль **Житель** — служебные действия исчезнут, а публичная история останется.
6. Откройте **Аналитику** и скачайте CSV-отчёт.

Полный сценарий защиты: [`docs/PITCH_5_MIN_RU.md`](docs/PITCH_5_MIN_RU.md).

## Технологии

| Слой | Решение |
| --- | --- |
| Язык | TypeScript 5.9 |
| UI | React 19, Next/Vinext |
| Стили | нативный CSS, без тяжёлой UI-библиотеки |
| Данные MVP | типизированная демо-база + localStorage |
| Карта MVP | Leaflet; CARTO/OSM, OpenTopoMap и Esri World Imagery |
| PWA | Web App Manifest + Service Worker |
| Аналитика | SVG/CSS, CSV через Web API |
| Деплой | Cloudflare Worker-совместимая сборка |

## Производительность

- Leaflet загружается динамически только при появлении карты;
- карта и повторяющиеся SVG-компоненты мемоизированы;
- обработчик выбора сигнала стабилизирован и не перезапускает карту при
  несвязанных изменениях интерфейса;
- карта изолирована через CSS containment, маркеры отрисовываются на Canvas;
- анимации ограничены `transform`/графическими свойствами и отключаются при
  `prefers-reduced-motion`;
- сетевые listeners, таймеры, Leaflet-события и `requestAnimationFrame` имеют
  cleanup;
- Service Worker кеширует только успешные same-origin GET-ответы и не блокирует
  Range-запросы;
- интерфейс использует нативный CSS без тяжёлого UI-kit.

## Архитектура и логика скоринга

Основной поток:

`Житель → наблюдение → автоскоринг → оператор → исполнитель → публичный результат`

Приоритет MVP считается детерминированно и объяснимо:

```text
базовый риск категории
+ 10 за непосредственную угрозу
+ 7 за фото-доказательство
+ 3–6 за полноту описания
= итог 0–98
```

Это baseline для безопасной демонстрации. На следующем этапе его можно дополнить компьютерным зрением, дедупликацией по георадиусу и прогнозной моделью, сохранив обязательную проверку экспертом.

Подробности: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Данные, безопасность и лицензии

- В репозитории нет ключей, паролей и персональных данных.
- Демо-события вымышлены и не утверждают, что реальные нарушения происходили в указанных местах.
- Подложки карты загружаются только при наличии сети; интерфейс, обращения и сохранённые данные продолжают работать без них.
- На карте сохраняется атрибуция OpenStreetMap, CARTO, OpenTopoMap и Esri в соответствии с условиями поставщиков.
- В пилоте точные координаты и оригиналы фото должны храниться в закрытом контуре, а публичная карта — показывать обобщённую геопозицию.
- Все зависимости перечислены в `package-lock.json`; используются компоненты с открытыми лицензиями.
- `npm audit` возвращает 0 уязвимостей после обновления Next, Vite, React и
  Cloudflare toolchain.
- Код проекта распространяется по лицензии MIT.

## Масштабирование после хакатона

1. PostgreSQL/PostGIS или Cloudflare D1 для общей базы обращений.
2. R2/S3 для фото с антивирусной проверкой и удалением EXIF.
3. Авторизация госорганов, RBAC и неизменяемый журнал действий.
4. Дедупликация близких обращений, интеграция IoT и открытых данных.
5. CV-модель для предварительного распознавания загрязнений.
6. Мультиязычность RU/KZ/EN и межрегиональный контур Каспия.
7. При необходимости — Expo-клиент поверх того же API для App Store/Google Play.

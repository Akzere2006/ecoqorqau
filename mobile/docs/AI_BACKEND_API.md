# Контракт AI backend

Мобильное приложение никогда не должно содержать секретный ключ AI-провайдера.
Переменная `EXPO_PUBLIC_AI_API_URL` указывает только на контролируемый backend.

## POST /assistant

Запрос:

```json
{
  "question": "Я увидел нефтяную плёнку. Что делать?",
  "locale": "ru-KZ"
}
```

Ответ:

```json
{
  "answer": "Не приближайтесь к пятну..."
}
```

## POST /vision/analyze

Текущий MVP передаёт URI только как демонстрационный контракт. Production
реализация должна загружать файл через временный signed upload и передавать
серверу идентификатор объекта, а не локальный `file://` URI.

Ответ:

```json
{
  "category": "oil",
  "title": "Признаки нефтепродуктов",
  "summary": "Обнаружена радужная плёнка...",
  "risk": "critical",
  "confidence": 0.94,
  "detected": ["радужный спектр", "плёнка на воде"],
  "nextStep": "Не прикасайтесь к воде...",
  "model": "remote-ai"
}
```

Допустимые категории: `plastic`, `oil`, `wildlife`, `illegal_fishing`, `water`.
Допустимые уровни риска: `low`, `medium`, `high`, `critical`.

## Минимальная безопасность backend

- rate limit по устройству и IP;
- ограничение MIME-типа и размера файла;
- удаление EXIF после извлечения разрешённых полей;
- серверное SHA-256 хеширование исходных байтов;
- malware scan и изолированное object storage;
- короткоживущие signed URLs;
- журнал моделей, версий prompts и результатов;
- модерация и обязательная экспертная верификация критических сигналов;
- отсутствие автоматического юридически значимого решения только на основе AI.
